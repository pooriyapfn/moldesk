# CLI usage

The typical MoleculeDesk workflow is: check your machine, install a model, confirm it's installed, then manage it.

```bash
moldesk doctor              # detect hardware, Python, Docker, CUDA
moldesk install proteinmpnn # install a model
moldesk list --installed    # confirm what's installed
moldesk uninstall proteinmpnn --yes
```

## `moldesk doctor`

Detects your system and hardware, and explains compatibility for Python, Docker, CUDA, GPU, RAM, and disk against the models in the registry.

## `moldesk list`

Shows every model in the registry, its status (`available`, `beta`, or `planned`), and — with `--installed` — which ones are currently installed on your machine.

```bash
moldesk list
moldesk list --installed
```

## `moldesk install <model>`

Installs a model. By default this shows a plan and asks for confirmation; pass `--yes` to skip the prompt (useful in scripts/CI).

```bash
moldesk install proteinmpnn
moldesk install ligandmpnn --yes
moldesk install proteinmpnn --reinstall --yes
```

Under the hood, `install` gives Python models a pinned source checkout and an isolated `uv`-managed virtual environment, downloads any required checkpoints into a content-addressed cache (verified by SHA-256), and promotes the installation atomically — so a failed reinstall never leaves you with a broken model.

## `moldesk uninstall <model>`

```bash
moldesk uninstall proteinmpnn --yes
```

Removes the model's installed environment and state, but retains shared cached downloads (like checkpoints) so another model — or a later reinstall — can reuse them.

## `moldesk run <model> <input>`

Runs an installed model against an input file and reports the outcome.

```bash
moldesk run proteinmpnn structure.pdb
moldesk run proteinmpnn structure.pdb --output ./results  # also copy outputs here
moldesk run proteinmpnn structure.pdb --param <key>=<value>
moldesk run proteinmpnn structure.pdb --json               # machine-readable result
```

MoleculeDesk prints the run status and the path to each declared output as the run completes, plus the run directory it used. Pass `--output <dir>` to also copy the output files into a directory of your choice.

### Running on Runpod

Boltz-2 and ProteinMPNN can run on your own Runpod account instead of locally. Connect once, preview the quote, then run:

```bash
moldesk cloud connect runpod
moldesk run proteinmpnn structure.pdb --compute runpod --cache-policy ephemeral \
  --max-budget 2 --max-lifetime 3600 --dry-run   # print the quote only
moldesk run proteinmpnn structure.pdb --compute runpod --cache-policy ephemeral \
  --max-budget 2 --max-lifetime 3600             # asks for each acknowledgment, then approval
```

`--cache-policy` is required: `ephemeral` keeps nothing after the run (supported), `persistent` keeps a reusable model cache on a billed network volume (experimental). `--max-budget` and `--max-lifetime` are required too. `--gpu`, `--max-gpu-price`, `--datacenter`, `--gpu-image` and `--cpu-image` tune where and on what the run happens. Without a terminal, pass `--yes --accept-lifetime-risk`; `--yes` alone is refused.

Shutdown is best effort: if MoleculeDesk closes or loses connection, your Pod may keep running and charging. Inspect or clean up with:

```bash
moldesk cloud status
moldesk cloud resources
moldesk cloud recover <run-id>
moldesk cloud cache list
moldesk cloud cache delete boltz
```

See the [Runpod cloud execution guide](/docs/guides/runpod-cloud-execution) for costs, limits and what was validated.
